4. Mention two reasons why branches are used in a Git repository.
------------------------------------------------------------------------
1) You can work on a new feature or bug fix without messing up the main
   branch. If it doesn't work out, you just delete the branch.
2) Multiple people can work on different things at the same time, then
   merge their work back into main when it's ready, usually through a
   pull request so someone can review it first.

------------------------------------------------------------------------
5. What is the difference between git log and git status?
------------------------------------------------------------------------
The command git log shows the history of commits that have already been
made (hash, author, date, message).

The command git status shows what's going on right now: which branch
you're on, whether you're ahead or behind the remote, and which files
are modified, staged, or untracked and haven't been committed yet.

8. In the context of object-oriented programming (I) What is
   inheritance? (II) What is polymorphism? (III) What is
   encapsulation?
------------------------------------------------------------------------
(I) Inheritance - a class can be based on another class and get its
    variables and methods, then add or override its own. In this repo,
    Car inherits from PoweredVehicle, which inherits from Vehicle, and
    Bicycle inherits directly from Vehicle.

(II) Polymorphism - you can treat objects of different classes as their
    base class, and the right version of a method still gets called at
    runtime. In C++, this works through virtual functions. In main.cpp,
    the vehicles are stored in a Vehicle** array, but calling
    toString() or mileageEstimate() runs the Car or Bicycle version.

(III) Encapsulation - keeping a class's data private and only letting
    outside code change it through the class's own methods. For
    example, Car's engine size is private and can only be set through
    setEngineSize(), which only accepts "unknown", "small", "medium",
    or "grande".

9. What is the main difference between the "Dictator and Lieutenants"
   workflow and the "Integration manager" workflow?
------------------------------------------------------------------------
The main difference is who handles merging and conflicts. In the
Integration Manager workflow, it's centralized - every developer pushes
to their own public repo, and one integration manager merges everyone's
changes into the blessed repo and fixes all the conflicts.

In the Dictator and Lieutenants workflow, that work is split up.
Developers push to an assigned lieutenant, and each lieutenant merges
the changes from their group and fixes those conflicts. Then the
dictator merges the lieutenants' repos and is the only one who can push
to the blessed repo.

------------------------------------------------------------------------
10. How would a team of 100 developers benefit from following the
    "Dictator and Lieutenants" workflow instead of the "Centralized"
    workflow?
------------------------------------------------------------------------
With Centralized, all 100 people push to the same repo, and each person
has to pull and fix conflicts before they can push. With that many
people, someone has almost always pushed before you, so you keep pulling
and fixing conflicts over and over. There's also nothing stopping
someone from pushing broken code straight to the main repo.

With Dictator and Lieutenants, each lieutenant only deals with a smaller
group, so merging is more manageable and the lieutenant can review code
for their part of the project. Since only the dictator pushes to the
main repo, code gets checked twice before it gets there, and no single
person has to merge work from all 100 developers.
